# iqdb-eval v0.1.0 — Scaffold

**The repository bootstrap.** v0.1.0 establishes the structure, tooling, and
quality gates the evaluation harness is built on — no domain logic yet. It
exists so the implementation lands one verified step at a time onto a foundation
that already enforces the iQDB engineering standard.

## What is iqdb-eval?

The evaluation harness of the iQDB vector database. It measures the numbers a
vector index lives and dies by — **recall@k**, **latency percentiles**, and
**throughput** — and makes them reproducible. It is generic over the
`iqdb-index` `Index` / `IndexCore` traits, so a single harness call works against
`iqdb-flat`, `iqdb-hnsw`, `iqdb-ivf`, or any future index, and it uses
`iqdb-flat` as the exact oracle to generate ground truth when none is supplied.

## What's next

- **v0.2.0 — recall@k against flat ground truth + report types.** The hard part,
  not deferred: correct recall@k computed against the true top-k from an exact
  `iqdb-flat` oracle (never approximated), with the row-index ↔ `VectorId::U64`
  convention documented loudly and the core invariants property-tested.
- **v0.3.0 — latency (p50/p95/p99) + throughput harness.** Nearest-rank
  percentiles over per-query wall-clock samples, with build cost excluded by
  construction.
